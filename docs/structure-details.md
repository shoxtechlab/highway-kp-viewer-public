# 橋梁・トンネルの諸元表示

[ドキュメント案内](README.md#利用ガイド) / 利用ガイド 04 / **橋梁・トンネルの諸元**

確認対象：`2026.11.7-beta.10`。構造物ラベルの操作と、表示する値の根拠を説明します。

通常の路線ビューで、橋梁・トンネルのラベルから諸元を確認できます。E18・E30での試験導入を経て、構造物データがある全路線へ適用しています。

## 操作

- マウス：ラベルへポインターを重ねると表示し、離すと閉じます。クリックすると固定表示します。
- タッチ：1タップで表示します。再タップ、外側のタップ、画面のスクロール操作で閉じます。
- Escape、画面サイズ変更でも閉じます。

ラベルの選択によるKP移動・赤枠表示は引き続き利用できます。端末の種類を画面幅だけで決めず、マウスのポインターイベントとクリック／タップを区別しています。

ポップアウトは固定の小型パネル（通常182px幅）です。長い名称は折り返し、画面端では位置を調整します。

## 表示項目

| 項目 | 表示 |
| --- | --- |
| 名称・種別 | 橋梁／トンネルと構造物名 |
| 方向 | 選んだラベルの方向。路線固有の方向名に対応 |
| 始点・終点 | 元データの路線KP。小数第3位へ四捨五入し、不要な末尾ゼロは省略 |
| 延長 | 収録された延長を1m単位へ四捨五入。OSM由来と判定した値は欄ごと非表示 |

KP差や`osm_geometry_length_m`から延長を再計算して表示することはありません。KPの出典と延長の出典は別に判定するため、KPがOSMクリックで、延長が公式台帳という項目では延長を表示します。

出典情報がない従来データでは、収録済みの`length_m`を使います。この扱いは公式値であることを保証しません。路線別データの出典整備は今後の課題です。

管理事務所版で区間が切り詰められても、ポップアウトは元の構造物の始終点・延長を表示します。複合路線でも内部通算KPへ変換する前の値を参照します。

## 同名構造物の識別

名称だけで検索せず、元データに紐づく`structureKey`を描画要素へ引き継ぎます。

1. 元データに永続的な`id`があれば優先します。
2. なければ、区間・種別・名称・上下線の始終点KPからキーを作ります。
3. 同じキーが重なる場合は出現順の番号で分離します。
4. キーを管理範囲の切り詰め・KP変換より前に付けます。
5. 諸元の参照・赤枠選択・再クリック判定で同じキーを使います。

キーは画面内の参照用で、原本を書き換えません。元データにIDのない項目は、KP修正や完全重複項目の並べ替えでキーが変わり得るため、外部から恒久参照するIDとしては使いません。

主な実装は`js/structureIdentity.js`、`js/structureDetails.js`、`js/structure.js`、`js/svgV2.js`です。
